# Dev log 2026-11-04

**Phase:** 6c (Ship)
**Branch:** phase-6c-ship

## Done
- App icon: a speech bubble with a check (`build/icon.svg`), rendered to `build/icon.png` by `scripts/render-icon.cjs` and used for all three installers.
- Electron hardening:
  - Fuses in the packaged binary: no run-as-Node, no `NODE_OPTIONS`, no inspect flags; asar integrity and load-only-from-asar on.
  - Subframe navigation and redirects are blocked.
  - IPC accepts calls only from the main window's main frame.
  - The data folder is limited to its owner (0700) on macOS and Linux.
- Startup failure: if the data won't open, a dialog now shows the newest backup and how to restore it, with an "Open data folder" button (`src/main/startup.ts`, tested).
- Installers: version 0.9.0. NSIS installs per user (no admin password) with desktop and Start-menu shortcuts. The macOS build is an unsigned universal dmg; the Linux build is an AppImage. Each file is named `Catalyst-Discovery-CRM-<version>-<os>-<arch>`.
- Release workflow (`.github/workflows/release.yml`): a `v*` tag builds and tests on Windows, macOS and Linux, then creates a draft GitHub Release. Actions are pinned to commit SHAs, and only the release job can write.
- Student install guide (`docs/guides/install-guide.md`), linked from home and the README.
- Fixes from the security audit:
  - `saveVenture` only edits the open venture.
  - The data folder is created and locked before the database is opened.
  - Imported timestamps from the future are capped at the import time, so a crafted file can't hide later edits.
- Fixes from ponytail-review:
  - The restore steps in the open-failure dialog now say to move the `-wal` and `-shm` files too. A stale WAL file could corrupt the restored backup.
  - Looking up the newest backup can no longer throw inside the error handler.
- Dev tooling: web-design-guidelines is no longer committed (no redistribution license) and is installed locally instead; security-audit keeps its LICENSE. `plugins.md` updated to match.
