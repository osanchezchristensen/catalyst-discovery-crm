# Dev log 2026-11-12

**Phase:** 9c (v0.12.0 part 3: summary PDF and Trash)
**Branch:** `phase-9c-summary-and-trash`

## Done
- Trash (#14):
  - Migration v8 adds `deleted_at` to contacts and interviews. Deleting moves a row to Trash, and every list, count, chart, readiness check, search and link skips rows in Trash.
  - The confirmation now says "Move … to Trash". The message after a delete has an **Undo** button, and it stays until it is used or dismissed.
  - Settings → Trash lists each item with the date deleted, the days left, **Restore** and **Delete forever** (for consent requests, where a real delete is needed now).
  - At startup, after the launch backup, rows in Trash for more than 30 days are deleted along with their attachment files.
  - Workspace import: a delete or a restore counts as an edit, so the newest change wins. Files from before v8 import as not deleted.
- Summary PDF (#12):
  - A **Summary PDF** button on Viability and in File → Summary PDF… opens a preview. It holds the venture, readiness, up to 5 riskiest hypotheses, the 3 newest quotes and the latest decision.
  - **Save as PDF** uses Electron's `printToPDF` (no new dependency). Print styles show only the summary sheet, which is fixed to one Letter page.
- Checked in the running app at 1024×700:
  - Delete contact → Undo toast → Undo restores the contact.
  - Delete again → the contact is listed in Settings → Trash → Restore brings it back.
  - Viability → Summary PDF → the preview → Save writes a 1-page Letter PDF. The PDF was opened and checked; the save dialog was stubbed in the main process.

- Added "Delete forever" to Trash (not in the original plan). The PRD says a contact can be deleted on request, and that shouldn't have to wait 30 days.
